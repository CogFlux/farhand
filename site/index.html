Remote hands for coding agents.

FarHand moves every command and file operation of OpenCode, Claude Code or Codex onto a Linux machine over SSH. The agent works there. Your laptop — and every credential on it — stays here.

› run the tests ⚙ farhand_remote_bash [command=cargo test] → devbox:~/myapp test result: ok. 48 passed › upload the assets folder ⚙ farhand_upload [local=~/FarHand-Outbox/assets → ~/myapp/assets] Uploaded 23 files, 1.4 MB › and the .env ⚙ farhand_upload [local=~/FarHand-Outbox/.env] denied: `.env` looks like credential material (rule: denied-filename). FarHand never uploads credentials.

Why not just run the agent on the server?

Because then the agent's own configuration lives there: API keys, OAuth tokens, MCP secrets, editor state. Anyone with access to the server has your accounts. Running the agent locally keeps that material on a machine you control and lets you keep using the client you already have — Claude Code's terminal, OpenCode's TUI, Codex — while the work itself happens elsewhere.

FarHand is an MCP server. It takes the agent's local bash, read, write, edit, glob and grep away and hands back the same tools pointed at the remote, over your existing ssh setup. One binary, one config file per project, no agent on the server.

RemoteCommands run in the remote user's login shell, in the configured workdir. Plain Linux; nothing to install.

Each project is a folder on your machine with a .farhand.toml that names the host and the remote working directory. Open the agent there and it is remote; open it anywhere else and it is an ordinary local session. Prompts like "list the files" or "run the tests" mean the remote workdir — the model is told so, and the local tools are disabled, not merely discouraged.

[remote]
host = "devbox"            # an alias from ~/.ssh/config
workdir = "~/myapp"        # where commands start

[local]
allowed_dirs = ["."]       # the only local folder the model may see

[approval]
mode = "ask"               # ask | auto | strict
askMutating tools — remote_bash, remote_write, remote_edit, upload, download — need your approval in the agent's own prompt; reads run freely. autoEverything runs. For a throwaway box or a scripted session. strictEvery call, including reads, asks first.

What never leaves your machine

Every byte headed for the remote — command text, file content, edits, uploads — passes the secret guard first. A refusal names the rule, never the matched text, and there is no override flag.

By pathBy content
.env*, *.pem, *.key, id_*, .netrc, .npmrc, credentials*, *service-account*.json, *.tfstate, agent configs (opencode.json*, .mcp.json, .farhand.toml), anything under .ssh, .aws, .gnupg, .kube, .config, .claude, .opencode, .codex, … Private-key blocks, sk-…, ghp_… / github_pat_…, AKIA…, AIza…, xox…, Stripe keys, JWTs, Authorization: Bearer …, URLs with embedded passwords, and api_key = "<24+ random chars>" style assignments.

The local side is closed

  • The only process FarHand starts locally is ssh to the configured host. No model-supplied string reaches a local command line, and there is deliberately no local curl.
  • Local reads are the allowlist minus credentials: symlinks are followed before the containment check, and files the guard would refuse to upload are hidden from the model entirely.
  • Downloads cannot plant anything an editor or agent executes on opening a folder — .vscode, .git, .husky, .claude, CLAUDE.md, .farhand.toml — nor credential-shaped names. One refused name aborts the whole download before a byte is written.
  • Host keys are checked strictly. A .farhand.toml inside a cloned repository cannot point the agent at a machine you never connected to.
  • Your local environment is never forwarded. Every call, including refusals, is one line in ~/.local/share/farhand/audit/.

The remote is the model's sandbox: give that account only what it should have. The guard is a tripwire against accidents, not a substitute for keeping secrets out of the allowlisted folder.

Tools the agent gets

ToolWhat it does
remote_bashRun a command on the remote. Bounded output, remote timeout, local watchdog.
remote_readRead a remote file with line numbers; offset/limit page through it.
remote_write / remote_editCreate or overwrite a file; replace an exact, unique string. CRLF files stay CRLF.
remote_ls / remote_glob / remote_grepls -la, rg --files -g, rg -n on the remote (falls back to find/grep).
local_ls / local_readLook inside the allowlisted local folder, and only there.
upload / downloadMove files between that folder and the remote, guard-checked in both directions.
remote_infoHost, workdir, connection state, allowed folders, audit location.

One server, three agents

farhand install <agent> writes the agent's own configuration: the MCP server, the fence that disables its local tools, and the translation of FarHand's approval modes into the agent's permission system.

OpenCode

A plugin that adds the MCP server per project, disables the built-in tools, maps ask/auto onto OpenCode permissions and shows a toast if the config is broken.

farhand install opencode

Claude Code

MCP server plus a PreToolUse hook that denies Bash, Edit, Read… in remote projects and applies your approval mode to FarHand's tools.

farhand install claude-code

Codex CLI

An [mcp_servers.farhand] entry with per-tool approval modes; at project scope the built-in shell is turned off and the sandbox set read-only.

farhand install codex

Anything else that speaks MCP over stdio works with farhand serve --config /path/to/.farhand.toml.

Install

One static binary for macOS and Linux (Apple Silicon, Intel, x86_64, aarch64). The remote needs nothing beyond a standard shell and SFTP; ripgrep there makes search faster.

curl -fsSL https://raw.githubusercontent.com/CogFlux/farhand/main/install.sh | sh

Downloads the release for your platform into ~/.local/bin and verifies its SHA-256. FARHAND_BIN_DIR changes the location.

npm i -g farhand        # or: npx farhand ...

A dependency-free wrapper that fetches the matching release binary on first run.

cargo binstall farhand   # prebuilt
cargo install farhand    # builds from crates.io
git clone https://github.com/CogFlux/farhand.git && cd farhand
cargo install --path crates/farhand --locked

Then

farhand install opencode          # or claude-code / codex
cd ~/projects/myapp-remote        # a folder for this remote project
farhand init > .farhand.toml      # edit host and workdir
farhand check                     # connects once, prints what the model will be told
